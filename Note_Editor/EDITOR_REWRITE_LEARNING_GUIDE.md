# 音符編輯器：閱讀與從頭重寫指南

這份指南的目標是讓你能自己接手編輯器邏輯。建議保留目前的頁面排版、CSS、音樂播放和圓形預覽，先重寫「音符資料如何建立、選取、修改、移動、刪除，以及如何匯入匯出」。每次只完成一種行為，確認資料流清楚後再接下一種。

## 先從哪裡讀

不要一開始就從畫布某個 `onClick` 往下追到底。先看資料怎麼進來、長什麼樣子、最後怎麼出去，再讀 UI 如何改它。

### 1. 先看音符資料格式

打開 `src/pages/control.jsx` 的 `dataProcessing` 和 `src/pages/header.jsx` 的 `handleDownloadChart`。

先回答這幾個問題：

- CSV 的前兩列分別是什麼？第三列開始有哪些事件種類？
- `note`、`drag`、`rotate` 各自有哪些欄位？時間與軌道用什麼單位？
- 匯入時 `chartOffset` 加在哪些時間欄位？匯出時在哪裡扣回？
- 哪些欄位只供畫面或預覽使用，不應寫回 CSV？

把三種事件的欄位寫在紙上。這就是編輯器的「資料契約」；後面所有功能都應該遵守它。

### 2. 再看狀態如何變化

讀 `src/pages/noteEditorState.jsx`，先看 `noteEditorReducer`，再看它提供的操作：

- `replaceNotes`：匯入一份譜面
- `selectNote`：選取原始陣列中的某個事件
- `createNote`：建立事件並選取新事件
- `updateNote`／`applySelectedNote`：更新事件
- `deleteSelectedNote`：刪除事件
- Delete 快捷鍵：呼叫相同的刪除操作

讀 reducer 時，每個 action 都只追三件事：**收到什麼、回傳什麼新狀態、哪些元件會因此更新**。特別留意 `selectedIndex` 必須始終指向現存事件；刪除事件後，索引也要跟著更新或清空。

### 3. 接著看不依賴 React 的規則

讀 `src/pages/noteEditorModel.js`。它應該放資料規則和時間／座標計算，不應該讀寫 React state。

建議依這個順序讀：

1. `clampNumber`、`clampInteger`：把數值限制在允許範圍。
2. `snapTime`：將時間吸附到節拍格線。
3. `createNoteData`：根據事件種類建立資料物件。
4. `getNoteFormValues`、`createNoteUpdates`：把事件資料轉成表單值，再把表單值轉回更新內容。
5. `createEditorTimeline`：建立時間、畫布 x 座標、軌道 y 座標、格線索引與拖曳限制的換算規則。

每看一個函式，就用一組具體數字手算一次。例如 BPM 120 時，一拍是多少毫秒？畫布每秒 70 像素時，1500 毫秒落在 x 的哪裡？這樣能看出單位或 offset 有沒有混淆。

### 4. 最後讀畫布和表單

讀 `src/pages/editorCanvas.jsx` 時，建議依順序看：

1. `Editor`：讀取設定，建立時間軸模型，提供給畫布子元件。
2. `ChartTrack`：點空白畫布時，怎麼把 pointer 座標轉成新增事件所需的時間和軌道。
3. `ChartEvents`：`note`、`drag` 如何顯示、選取和拖曳。
4. `RotateEvents`：`rotate` 為什麼在另一條軌道上，以及它的 y 座標如何固定。
5. `Playhead`、`TimeRuler`：播放位置如何轉成畫布座標，以及使用者拖曳或點標尺後怎麼 seek。

然後讀 `src/pages/noteEditor.jsx`：清單保留原始索引來選取事件；表單先編輯自己的 draft，按套用後才更新譜面。這能避免每打一次字就直接改動正式資料。

最後看 `src/App.jsx`：它主要組裝 UI、保存 BPM／offset／音樂長度等設定，並把譜面交給匯出和圓形預覽。看完應能畫出這條簡單資料流：

```text
使用者操作
  → 轉成領域資料（時間、軌道、欄位更新）
  → reducer 更新譜面
  → 清單、表單、畫布和預覽重新讀取同一份譜面
```

## 從頭重寫時的思考步驟

每做一個功能，先寫下以下五點，再開始寫 JSX：

1. **輸入是什麼？** 例如 pointer 的 x/y、事件索引、表單欄位或鍵盤按鍵。
2. **規則是什麼？** 例如時間需要吸附、軌道限制在 1–31、rotate 的 y 不可改變。
3. **狀態要怎麼變？** 明確寫出操作前後的事件物件。
4. **畫面要怎麼反映？** 哪些形狀、欄位或選取樣式會更新？
5. **資料最後怎麼輸出？** 是否符合 CSV 欄位和 offset 慣例？

若一個函式同時讀 pointer、算拍點、建立音符、呼叫 state setter，又產生 Konva 元件，就先拆開。通常可以分成：

```text
事件處理（React / Konva）
  → 純計算（時間吸附、座標換算、欄位整理）
  → 狀態操作（reducer action）
  → 畫面依狀態重新繪製
```

### 建議重寫順序

#### 第 0 階段：保留舊版，先固定規格

先抄下三種事件的資料格式、offset 正負方向、時間單位、軌道範圍和 drag 的起訖規則。選一份小譜面當範例，記錄匯入後的物件和預期匯出內容。

**完成條件：** 不看程式碼也能說明一個事件從 CSV 進來、在畫布上移動、再匯出時欄位如何改變。

#### 第 1 階段：先重寫純資料函式

先不要碰 React 或 Konva。建立小函式來處理：

- 事件建立：給定 type、time、land 和設定，回傳完整事件物件。
- 數值限制：時間、軌道和方向如何限制或正規化。
- 時間吸附：輸入毫秒時間，輸出吸附後時間。
- 表單轉換：事件物件轉欄位 draft；draft 轉成 patch。

**完成條件：** 每個函式都只靠參數與回傳值工作，不需要 `setState`、DOM 或 React。

#### 第 2 階段：整理單一狀態來源

讓 reducer 管理 `notes`、`selectedId`（或暫時沿用 `selectedIndex`）和目前建立工具的種類。用 action 表達使用者意圖，例如 `note/create`、`note/select`、`note/update`、`note/delete`、`chart/replace`。

新版本若還沒被其他程式依賴，建議從一開始就給每個內部事件穩定的 `id`，用 `selectedId` 取代陣列索引。匯出 CSV 時只挑 schema 欄位，因此 `id` 不會寫出去。若先沿用 index，也要確保排序只改顯示順序，刪除後選取索引會同步調整。

不要另外保存一份 `selectedNote` 物件；選取事件應從 `notes` 和 `selectedId` 推導，避免資料更新後兩份狀態不一致。

**完成條件：** 建立、選取、更新、刪除都只經過 reducer；清單、表單和畫布讀的是同一份狀態。

#### 第 3 階段：單獨解決時間軸數學

先固定單位，再定義換算：

```text
時間：毫秒
比例尺：每秒幾個像素
x = 時間毫秒 / 1000 * 每秒像素
```

再決定 offset 的規則：CSV 匯入時加多少、畫布格線如何起算、匯出時扣多少。吸附公式應集中在一處，不要在新增、拖曳、表單各自寫一份。

思考邊界情況：沒有音樂（duration = 0）、offset 是負值、游標超出畫布、時間小於 0 或超過歌曲長度、BPM 或 beat 不合法。

**完成條件：** 給定同一個時間與設定，新增、拖曳和尺標都依同一套單位與 offset 規則工作。

#### 第 4 階段：先畫靜態畫布

用固定範例資料，只畫時間尺、格線、軌道和三種事件。暫時不加選取、拖曳或建立行為。把資料轉成 Konva 的 x/y 和顏色，確認畫布只負責呈現。

**完成條件：** 傳入一份事件陣列，就能正確畫出所有事件，且更換資料後畫面自然更新。

#### 第 5 階段：一次加入一種互動

依序完成，不要同時做全部：

1. 點空白畫布新增 `note`。
2. 點事件選取，清單與表單同步反映選取結果。
3. 拖曳 `note`，放開後只提交一次 update。
4. 選取 `drag` 後分別拖曳起點和終點。
5. 在 rotate 軌道選取和拖曳 `rotate`。
6. Delete 按鈕與鍵盤 Delete 共用同一個刪除 action。
7. 播放線拖曳預覽，放開時才 seek 音樂。

每個互動都遵守「事件 → 換算 → action → reducer → 畫面」的順序。不要讓畫布直接修改事件物件。

#### 第 6 階段：加入表單 draft 和套用

選取事件時，把欄位複製成表單的暫存值。輸入過程只改 draft；按套用時，依事件種類整理成 patch，再送 reducer 更新。取消或換選取項目時，丟掉舊 draft 並載入新事件值。

**完成條件：** 輸入未套用前，畫布和清單保持不變；套用後三個視圖一起更新。

#### 第 7 階段：接回匯入、匯出和預覽

最後再接 CSV 讀取、下載、音樂時鐘和圓形預覽。這些是編輯核心的外圍功能，先讓核心可以建立、修改、刪除，再接外部資料來源較容易除錯。

**完成條件：** 匯入一份範例、做幾種編輯、匯出後，重新讀取檔案仍保留預期欄位與時間。

## 需要熟悉的程式知識

### JavaScript 基礎

- 物件與陣列：`map`、`filter`、`find`、展開語法、條件分支。
- 不可變更新：回傳新物件／新陣列，不直接改原物件。
- 函式輸入輸出：同一組輸入應得到可預期結果；理解純函式與副作用的差別。
- 數字處理：`Number`、`Number.isFinite`、`Math.round`、最小／最大值限制。
- 模組：用清楚的匯入匯出界線分開資料、畫面和外部 I/O。

### React

- 元件、props、state，以及 state 改變後的重新繪製。
- `useReducer`：適合把多個相關狀態操作集中在 action 和 reducer。
- Context：只用來避免跨很多層傳遞共同資料；不需要為每個小值都建立 context。
- 受控輸入與 draft state：區分「正在輸入」和「已套用到譜面」。
- `useEffect`：用於事件監聽、訂閱和外部資源清理；不要用 effect 複製可推導的 state。
- callback/event handler：知道畫布事件何時發生，哪些操作應在拖曳開始、移動或放開時提交。

### 座標、時間與編輯器概念

- 毫秒與秒的轉換，以及時間軸的線性比例尺。
- clamp（限制範圍）、snap（吸附格線）、座標轉換。
- 以一份 canonical state 作為來源；選取項目、排序清單和畫布顯示都由它推導。
- 交易邊界：拖曳期間可顯示暫時位置，通常在放開時提交一次資料更新。

### React-Konva 與瀏覽器 I/O

- Konva 的 `Stage`、`Layer`、Shape、事件 bubbling、`dragBoundFunc` 和 `onDragEnd`。
- 了解 pointer 座標屬於哪個 Stage，避免把 DOM 座標和畫布座標混用。
- CSV parse/unparse、`File.text()`、Blob 和下載。
- Howler / Zustand 可以最後再讀：它們負責播放和共享音樂時間，不應決定音符資料格式。

## 寫程式時的幾個守則

- 先寫一個功能的輸入、規則、輸出，再寫元件。
- 時間／座標轉換只保留一份實作，其他地方呼叫它。
- action 用「使用者意圖」命名，不用 `setSomething` 拼湊散落的更新。
- 事件物件採不可變更新；不要讓畫布或表單直接改 `notes[index].time`。
- 畫面排序資料時保留穩定識別值；不要把排序後的 index 當原始資料索引。
- 除了明確的副作用邊界，純資料模組不 import React、Konva 或 Howler。
- 先把一種事件做完整，再複製規則到其他事件；共通的計算抽成小函式，差異留在事件種類分支。

## 建議你的第一個練習

先不要動畫面。打開 `noteEditorModel.js`，自己重寫以下三個函式並用手算案例確認：

1. `clampInteger(value, min, max)`：輸入超界時回傳邊界值。
2. `snapTime(time, config)`：以 BPM、beat 和 offset 算出最近格線時間。
3. `createNoteData(type, time, land, config)`：回傳符合 note／drag／rotate schema 的新物件。

然後畫出 reducer 的四種狀態轉移：建立、選取、更新、刪除。等這兩部分你能不看舊程式自行說明，再開始改 `ChartTrack` 的點擊新增。這樣一開始只需要處理資料規則，不必同時猜 React、Konva 和畫面排版。
